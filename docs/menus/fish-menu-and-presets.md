# Fishonmc menu and presets

- fishonmc menu (`menu/FishMenu`, `menu/MenuRows`, `menu/Locations`, `screen/FishMenuScreen`, setting `fishMenu`, `menuSize`): `MinecraftClientMixin` swaps a `GenericContainerScreen` for `FishMenuScreen` when the player just typed `/travel`, `/turbotravel`, `/stats` or `/crew`. /menu (title `할`) and the instance list (`Instance 4 (14/75)` items; it shares the crew title `핒`, so the screen hands it back to the chest as soon as its items arrive, `FishMenu.isInstanceList`) stay the server's own chest (luna, 2026-10-30: "the default guis, just bigger"; `chestScale` 3 makes them bigger, see `menu-controls.md`). The daily missions column and the foecollab daily mission flag (`compat/FoeMainMenu`) went with the main menu panel. The button-only menus (stats, quests, crew, and anything opened from inside our screen, such as the quest difficulty and tier pages and compendium pages) use the same screen; menus that need your inventory (sell, vault, tackle shop, armor, auction house) stay as the chest. The screen reads the real chest slots, so it keeps working while the server refills them, and a click sends `ClickSlotC2SPacket` straight away with no client side pickup. Escape clicks the menu's Return button when it has one, otherwise closes; E closes.
- The rebuilt look (2026-10-30, asked for by luna after seeing someone's /event gui; it replaced the big-icon tiles, the rearrange mode and its `menuCells`, and the `menuAccent`/`menuAccentOpacity` tile fill, whose saved keys are ignored now): one solid dark panel (at most 600 wide, inside the `menuSize` frame) with a 2 px accent gradient line on top (`Hypr.acc1/acc2`, luna's accent setting, not the orange of the screenshot). Header: the menu name in the accent, the fishing level, a bar and `1.18m/3.8m` from the profile head on the right (kept from your own last /stats page this session, so every tab shows it; empty until you open /stats). Tabs menu, travel, quests, stats, crew, event send that command (the same as typing it, not automation); the active one is underlined in the accent. "server menu" opens the chest (`FishMenu.bypass`), x closes. Footer hint bottom right.
- Rows (`MenuRows.of`): each server button is a 22 px row: its item (shulker, concrete and terracotta as flat colour swatches), its name in small caps, one dim line in sentence case, and on the right the `(a/b)` count from the lore with a thin bar (accent gradient, green when full; progress past the max, like the compendium's `11.85M/2.32M`, is full). The line is the first lore line that is not the name, not blank and not a small caps hint (`ᴄʟɪᴄᴋ ᴛᴏ ᴠɪᴇᴡ`; the server's small caps s is a plain s, so a hint is "no capital ascii letter and some small capital"); a quest joins `Catch 70x Rare fish` with `at Murray River`; a /travel place shows `Subtropical · Freshwater · -5°C`. Close and Return are not rows. The wheel scrolls the column under the mouse (the page wheel still turns pages first in paged menus). Hover shows the full item tooltip.
- Per menu: places (4+ items named after a location: /travel and compendium location pages) list the places with `lvl n` and the level bar (`FishMenu.info` from the tooltip, which only the compendium has, saved in `locationLevels` and reused in /travel) and beside them "best place to fish" (lowest three levels) and "bait at" the hovered place from the notes in `Locations`. Any other menu is one column of rows, two when they do not fit. In the quest menus the rows get the quest again marks (`QuestRedo`, see `quests.md`), and clicking a quest row tells `QuestRedo` which quest it was.
- The /event page (2026-10-30, luna: "/event doesnt have a custom ui which i specifically asked for"; `hud/EventPage`, `FishMenuScreen.drawEvent`): `/event` and its title `함` (`Glyphs` names it "event") open in the panel, with an event tab. The rows come from what `EventHud` read off the chest under the panel (`XpEstimate` keeps scanning `FishMenuScreen.original()`). Header: the event's name ("halloween 2026") and on the right your placement and points. Left: "thresholds" with `n / 7 reached`, one row per threshold head with its first two rewards and a `have/need` bar (full once reached), then the other items (missions book, river monster species, welcome, leaderboards) as rows. Right: "missions" with `n / m done`, every mission of the book: per catch (`50 pts each`), repeating (`2 pts every 100, 10 pts so far`), once (`400 pts`) or best weight; the wheel scrolls it. Not run in game yet.
- The /stats page (2026-10-30, luna wanted it like SkyCrypt; `menu/StatsPage`, `FishMenuScreen.drawStats`): your own and `/stats <player>` use the same layout. `StatsPage.read` takes it as a stats page when it has both "Fishing Profile" and "General Statistics". Gear is found by custom_data `type` (hat, armor with `piece`, reel, pole, line, pet, bait), the showcase by slots 2-6, the buttons by name (slot map in `fishonmc-research.md`). Header: the profile's name instead of "stats", its level, bar and xp, and the placement of a showcase item with a `Placement:` line ("#23 christmas event 2025"). Left: an `OtherClientPlayerEntity` wearing the chest, legs and boots (and a helmet if one shows up; `PresetsScreen.wearable`); the hat is a pack model on a leather boot, so it is only in the list. Another player's skin comes from the tab list when they are online, otherwise the default skin. Under it the five showcase slots, empty ones as faint boxes. Middle: armour (hat, helmet, chest, legs, boots) and rod (reel, pole, line with its durability bar), each row with rarity, quality and tier from the custom_data. Right: tiles power (profile), runes (Runes Breakdown), catches (General Statistics), bait stock (the bait), then the pet card with its level, equipped item and xp bar (full at MAX). Bottom: the other buttons (fishing menu, collections, power breakdown, level colours, admiral colours) as small text buttons. Everything clicks its own slot and shows its tooltip. Only your own page fills the header level of the other tabs. Not run in game yet.

- Travel marks (2026-10-29, asked for by luna; `Locations.mark`/`isTravelItem`, `HandledScreenMixin.travelMark`, `FishMenuScreen.drawTile`): the server adds `*FRENZY!*` to the name of a place in a frenzy (dumps 2026-10-24 `Oil Rig *FRENZY!*`, 2026-10-29 `Toledo Bend Reservoir *FRENZY!*`, the first lore line too) and nothing else changes in the item. That place gets green (`FRENZY`), the fabled event's place red (`FABLED`, the place from the `Visit the X to` chat line, kept by `ServerHud.fabledPlace()` until `Caught by`; lost on a restart). Frenzy goes before fabled. The fabled event leaves no mark in the /travel items (2026-10-29 dump), so it can only come from chat. In the plain /travel chest the slot gets a see-through square behind the item (only items with `custom_data {fastTravel:1b}`, so no other menu); in tacklebox's menu panel (setting `fishMenu`) the whole row. Always on, no setting. The check uses the full name string, not `Glyphs.plain`, in case the server puts the tag in a pack font. Root cause of "the frenzy tile is not green" (2026-10-29): luna's `fishMenu` was off, so /travel was the vanilla chest (the dump's screen is `class_476`) and the green was only drawn in tacklebox's screen. Witching Hour marks for Cypress Lake: luna said no. Tests: `TravelMarkTest`, `TravelMarksIntegrationTest`. Not seen in game yet.
- Presets (`screen/PresetsScreen`, swapped in by `MinecraftClientMixin` when `FishMenu.isPresets`): wardrobe cards, armor presets draw an `OtherClientPlayerEntity` with the set via `InventoryScreen.drawEntity`, parts presets draw their items big; a click on a card sends the equip slot click, and so does number key n for the nth card on the page (see `menu-controls.md`).
