# World display and totem pop

- Ported from luna's older fishutils mod (MIT, luna's own code), all only changing what the player sees:
  - Bobber: still bobber (`FishingBobberEntityMixin`), smooth cast (`EntityInterpolationMixin` + `display/SmoothCast`).
  - World: `EntityRenderManagerMixin` hides other bobbers (rule in `display/OtherBobbers`), nametag holograms and xp holograms (`display/Holograms` folds small caps and fancy digits). `PlayerNameLabelMixin` hides vanilla labels. `InGameHudOverlayMixin` hides the +xp action bar. `display/FlatLeaves` swaps leaf models with a `ModelLoadingPlugin` (models in `assets/tacklebox/models/block`).
  - `hud/BaitInfo` reads the rod `activeBait` custom_data (rarity colours for the menu screen).
  - Left out on purpose: the particle-based fish trail and bite countdown. luna didnt want them.
- Totem pop (2026-10-08, asked for by luna for pet drops; `Trigger.totem`, tab "3. totem" in `TriggerEditScreen`, `display/TotemPop`, `ItemLooks`, `PetHeads`): a trigger can show an item in vanilla's totem animation (`GameRenderer.showFloatingItem` only, no particles; the sound is the trigger's own). The item is an id, an item name (`{item}`, the real item from the inventory), `pet:{pet}` or `shard:{climate}`; lookup order and presets are in `triggers.md`. `PetHeads` learns each pet type's head (the `profile` of a `type:"pet"` item without a `skin`, saved as json in `petHeads`) and each shard's (`type:"armorShard"`) from the inventory or an open menu. Heads bundled in `data/tacklebox/petheads.json` (all 16 pet types plus hippo, all ten climate shards; the albino shard is a different thing and is skipped) are the fallback, so only a new pet type shows a plain head until seen. Not run in game yet.
  - Leaving spin (2026-10-29, luna: no spin back when it disappears, "it should spin like 300 degrees", keep turning the same way): vanilla `renderFloatingItem` runs 40 ticks on a curve (`TotemPop.curve`) that climbs to about 0.47 by tick 12, stays near 0.5 until tick 30, then runs to 1. The Y spin is 900 * \|sin(curve * pi)\|, so the item spins 900° in, holds, then spins 900° back while it flies off. For the mod's own pops `InGameOverlayRendererMixin` wraps the first `RotationAxis.rotationDegrees` call (the Y spin) and, once the curve passes 0.5, turns it 300° further the same way instead (`TotemPop.spin`, 900° to 1200°). Coming in, holding, the fly-off and the X/Z wobble stay vanilla. "The mod's own" is the exact stack `TotemPop` handed to `showFloatingItem` (`TotemPop.shown`), so a real totem of undying stays vanilla. The trigger's size setting checks the same stack (`TotemPop.size`; before 2026-10-29 a real totem after a trigger pop took that trigger's size). Tests: `TotemPopTest` (curve, spin, size), `TotemPopSpinIntegrationTest` (every frame of a pop, real totem keeps vanilla size and spin). Not run in game yet.
- Sneak height (2026-10-11, asked for by luna): `sneakHeight` (1.5 to 1.8, default 1.5, slider "sneak height" in `ViewmodelScreen`) is how far your own first person camera dips when sneaking. 1.5 is vanilla (eyes 1.62 to 1.27), 1.8 is no dip, in between is linear (`display/SneakHeight`). `CameraMixin` wraps the `getStandingEyeHeight` call in `Camera.updateEyeHeight` (the camera eases towards it, so the dip animation stays) only for the local player whose real pose is CROUCHING (`isInPose`, not `isInSneakingPose()`: `ClientPlayerEntity` overrides that with an input flag one tick behind the pose and eye height, which let vanilla's 1.27 through for one tick on every press, a visible dip even at 1.8; found 2026-10-11 from a camera log, pinned by `SneakHeightTest`); hitbox and the pose the server sees are untouched. Foecollab has no such setting. Checked in game 2026-10-11 at 1.8 and a middle value (luna: works perfectly).
- Chummer range ring (2026-10-17, asked for by luna; `display/ChummerText`, `ChummerRingGeometry`, `ChummerRing`; fishing page, group "chummer": `chummerRing` on by default, `chummerRingColor` green `0x41F55B`): a thin flat ring on the ground, 20 blocks out, around every placed chummer found by its hologram text. Details, gotchas and what to check in game: `huds/chummer-range.md`. Not run in game yet.
- Foecollab bait under bobbers (2026-10-18, luna: still showed with "hide other bobbers" on): foecollab's `FishingRodHandler.tickEntities` spawns a client side item display with the owner's bait under every bobber, other players too, so hiding the bobber entity left it. `FishingRodHandlerMixin` (by name, `require = 0`) cancels that tick for other players' bobbers while the setting is on, so no display is spawned or parsed (also less work in big groups). Same code in foecollab 3.1.0 and 3.1.3. Displays made before the setting was turned on stay until the bobber goes. Not run in game yet.
- Hide far displays (2026-10-18, asked for by luna; settings page "world", section "lag": `hideFarDisplays` off by default, `farDisplayRange` 8 to 64, default 24; `display/DisplayCull`, checked in `EntityRenderManagerMixin` for every `DisplayEntity` by distance to the camera): stops drawing the servers item, block and text displays beyond the range. Why: at spawn (679 entities, 225 item, 88 block and 47 text displays) luna measured about 200 fps with them and about 450 with `/tacklebox debug displays` hiding them all. Far text holograms (shop signs) go too, near ones stay. Not run in game yet.
- Black sky (2026-10-25, asked for by luna; `blackSky` off by default, toggle "black sky" on the world page; `SkyRenderingMixin`, `FogRendererMixin`): client only, the server clock and weather are untouched. `SkyRendering.updateRenderState` (tail) sets the sky colour black and zeroes stars, sunset glow and rain gradient; `renderCelestialBodies` is cancelled (no sun, moon, stars); `FogRenderer.getFogColor` returns black while the camera is in air (`ATMOSPHERIC`) only. Water fog stays vanilla (2026-11-15: pure black underwater was far too dark; 1.21.11's water fog is the biome's fixed dark blue, not time dependent, so it already looks like night), as do lava and powder snow. Block lighting is vanilla. Foecollab has no such option. Test: `BlackSkyIntegrationTest` (settings only). Gotcha (2026-11-15): Sodium Extra's own "sky" setting off makes the sky render as plain pale blue and black sky seems to do nothing; turn that setting on. Not run in game yet: check Sodium doesn't bypass the sky, the horizon is black, and rain still sounds/particles (not hidden).
- Hide block outline (2026-11-13, asked for by luna; `hideBlockOutline` off by default, toggle "hide block outline" on the world page, section "clutter"): `GameRendererMixin` makes `GameRenderer.shouldRenderBlockOutline` return false, so the outline around the block you are looking at is not drawn. Clicking and targeting blocks is untouched. Foecollab has no such option. Test: `BlockOutlineIntegrationTest` (settings only). Not run in game yet: check the outline is gone and that it also holds with Sodium.
- Crowds (2026-10-29, asked for by luna; settings page "world", section "crowds", all off by default; rules picked by Claude, luna said yes to them):
  - Hide nearby players (`hideNearPlayers`, `nearPlayersRange` 2 to 12, default 4; `display/NearbyPlayers`, checked in `EntityRenderManagerMixin`): only while your line is out, other players within the range of you or your bobber are not drawn, and neither are text displays or armour stands riding them or floating in the nametag window over them (0.7 blocks sideways, 1.75 to 4 above the feet). Crewmates and friends stay: `compat/FoeFriends` reads foecollab's `ProfileDataHandler.profileData.crewMembers` and `friends` by reflection once a second (empty without foecollab: then nobody is kept; tacklebox's own crew and friends lists wait for dumps of the crew members and friends menus). Only players listed in the tab list count, so the server's npcs (player entities too) stay; if fishonmc's tab list ever leaves real players unlisted, nobody gets hidden. Worked out once per world tick, not per frame. Hidden players can still be clicked. Foecollab has no such option.
  - Only my fish (`ownFishOnly`; `display/OwnFish`, `BobberTimer.onParticle`, `ClientPlayNetworkHandlerParticleMixin` now cancels): drops the `minecraft:fishing` approach particles (count 0) that swim to a bobber that is not yours, with the same owner rule as the bite countdown (within 10 blocks, line most perpendicular to the sideways speed). With no line out every fish particle that fits a bobber is dropped. Splashes and bubbles (count above 0) and particles that fit no bobber stay. The countdown now uses `OwnFish.owner` too: a candidate bobber has to be within 10 blocks of the particle (before only yours had to be).
  - Particle switches (`hiddenParticles`, a list of ids; `display/ParticleSwitches`, `mixin/ParticleManagerMixin` at HEAD of `ParticleManager.addParticle(ParticleEffect, 6 doubles)`, `screen/ParticleScreen`, link "particles" in the "clutter" section): one chip per particle type made since the game started (with a count) plus rain and the ones already off; a switched off type is dropped for everyone, your own particles too. That one call covers server packets and the game's own particles (rain splashes, emitters like the totem); block break particles are made another way and are not covered. Which types fishonmc uses for catch effects is not known, so the list is learned. Hooked in the particle manager, not `ClientWorld.addParticle` where foecollab injects (an inject there would also be fine).
  - Tests: `NearbyPlayersTest`, `OwnFishTest`, `ParticleSwitchesTest`, integration `CrowdsIntegrationTest` (settings and the rules only). Not run in game yet: check that npcs and crewmates stay, that players and their nametags come back when you reel in, that a neighbour's fish particles go and yours stay (also in rain), and which particle types show up after a catch.
