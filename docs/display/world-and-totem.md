# World display and totem pop

- Ported from luna's older fishutils mod (MIT, luna's own code), all only changing what the player sees:
  - Bobber: still bobber (`FishingBobberEntityMixin`), smooth cast (`EntityInterpolationMixin` + `display/SmoothCast`).
  - World: `EntityRenderManagerMixin` hides other bobbers (rule in `display/OtherBobbers`), nametag holograms and xp holograms (`display/Holograms` folds small caps and fancy digits). `PlayerNameLabelMixin` hides vanilla labels. `InGameHudOverlayMixin` hides the +xp action bar. `display/FlatLeaves` swaps leaf models with a `ModelLoadingPlugin` (models in `assets/tacklebox/models/block`).
  - `hud/BaitInfo` reads the rod `activeBait` custom_data (rarity colours for the menu screen).
  - Left out on purpose: the particle-based fish trail and bite countdown. luna didnt want them.
- Totem pop (2026-10-08, asked for by luna for pet drops; `Trigger.totem`, tab "3. totem" in `TriggerEditScreen`, `display/TotemPop`, `display/PetHeads`, preset "pet totem"): a trigger can show an item in vanilla's totem animation (`GameRenderer.showFloatingItem` only, no particles; the sound is the trigger's own). The item is an id or `pet:{pet}`: the chat line only names the pet type, so `PetHeads` learns each type's head (the `profile` component of a `type:"pet"` item without a `skin`, saved as json in `petHeads`) from any pet item in the inventory or an open menu; heads bundled in `data/tacklebox/petheads.json` (all 16 types plus hippo, taken from luna's settings 2026-10-08) are the fallback, so only a new pet type shows a plain head until seen. Climate shards work the same (`shard:{climate}`, learned from `type:"armorShard"` items, preset "shard totem"; bundled: subtropical, oceanic, savanna, semi-arid, rainforest, mediterranean, monsoon, subarctic, continental, arid (all of them); the albino shard is a different thing and is skipped). Both presets are anchored with `^` because other players' drops come as `! [n] name » PET DROP! ...`. The pet drop regex takes the rarity as an optional word (it is a glyph, stripped before matching, so the old `(?<rarity>\S+)` took the pet name as rarity). Not run in game yet.
- Sneak height (2026-10-11, asked for by luna): `sneakHeight` (1.5 to 1.8, default 1.5, slider "sneak height" in `ViewmodelScreen`) is how far your own first person camera dips when sneaking. 1.5 is vanilla (eyes 1.62 to 1.27), 1.8 is no dip, in between is linear (`display/SneakHeight`). `CameraMixin` wraps the `getStandingEyeHeight` call in `Camera.updateEyeHeight` (the camera eases towards it, so the dip animation stays) only for the local player whose real pose is CROUCHING (`isInPose`, not `isInSneakingPose()`: `ClientPlayerEntity` overrides that with an input flag one tick behind the pose and eye height, which let vanilla's 1.27 through for one tick on every press, a visible dip even at 1.8; found 2026-10-11 from a camera log, pinned by `SneakHeightTest`); hitbox and the pose the server sees are untouched. Foecollab has no such setting. Checked in game 2026-10-11 at 1.8 and a middle value (luna: works perfectly).
- Chummer range ring (2026-10-17, asked for by luna; `display/ChummerText`, `ChummerRingGeometry`, `ChummerRing`; world page, tile "chummer": `chummerRing` on by default, `chummerRingColor` green `0x41F55B`): a thin flat ring on the ground, 20 blocks out, around every placed chummer found by its hologram text. Details, gotchas and what to check in game: `huds/chummer-range.md`. Not run in game yet.
- Foecollab bait under bobbers (2026-10-18, luna: still showed with "hide other bobbers" on): foecollab's `FishingRodHandler.tickEntities` spawns a client side item display with the owner's bait under every bobber, other players too, so hiding the bobber entity left it. `FishingRodHandlerMixin` (by name, `require = 0`) cancels that tick for other players' bobbers while the setting is on, so no display is spawned or parsed (also less work in big groups). Same code in foecollab 3.1.0 and 3.1.3. Displays made before the setting was turned on stay until the bobber goes. Not run in game yet.
- Hide far displays (2026-10-18, asked for by luna; settings page "world", section "lag": `hideFarDisplays` off by default, `farDisplayRange` 8 to 64, default 24; `display/DisplayCull`, checked in `EntityRenderManagerMixin` for every `DisplayEntity` by distance to the camera): stops drawing the servers item, block and text displays beyond the range. Why: at spawn (679 entities, 225 item, 88 block and 47 text displays) luna measured about 200 fps with them and about 450 with `/tacklebox debug displays` hiding them all. Far text holograms (shop signs) go too, near ones stay. Not run in game yet.
