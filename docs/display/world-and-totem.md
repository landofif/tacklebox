# World display and totem pop

- Ported from l's older fishutils mod (MIT, l's own code), all only changing what the player sees:
  - Bobber: still bobber (`FishingBobberEntityMixin`), smooth cast (`EntityInterpolationMixin` + `display/SmoothCast`).
  - World: `EntityRenderManagerMixin` hides other bobbers, nametag holograms and xp holograms (`display/Holograms` folds small caps and fancy digits). `PlayerNameLabelMixin` hides vanilla labels. `InGameHudOverlayMixin` hides the +xp action bar. `display/FlatLeaves` swaps leaf models with a `ModelLoadingPlugin` (models in `assets/tacklebox/models/block`).
  - `hud/BaitInfo` reads the rod `activeBait` custom_data (rarity colours for the menu screen).
  - Left out on purpose: the particle-based fish trail and bite countdown. l didnt want them.
- Totem pop (2026-10-08, asked for by l for pet drops; `Trigger.totem`, tab "3. totem" in `TriggerEditScreen`, `display/TotemPop`, `display/PetHeads`, preset "pet totem"): a trigger can show an item in vanilla's totem animation (`GameRenderer.showFloatingItem` only, no particles; the sound is the trigger's own). The item is an id or `pet:{pet}`: the chat line only names the pet type, so `PetHeads` learns each type's head (the `profile` component of a `type:"pet"` item without a `skin`, saved as json in `petHeads`) from any pet item in the inventory or an open menu; heads bundled in `data/tacklebox/petheads.json` (all 16 types plus hippo, taken from l's settings 2026-10-08) are the fallback, so only a new pet type shows a plain head until seen. Climate shards work the same (`shard:{climate}`, learned from `type:"armorShard"` items, preset "shard totem"; bundled: subtropical, oceanic, savanna, semi-arid, rainforest, mediterranean, monsoon, subarctic, continental, arid (all of them); the albino shard is a different thing and is skipped). Both presets are anchored with `^` because other players' drops come as `! [n] name » PET DROP! ...`. The pet drop regex takes the rarity as an optional word (it is a glyph, stripped before matching, so the old `(?<rarity>\S+)` took the pet name as rarity). Not run in game yet.
- Sneak height (2026-10-11, asked for by l): `sneakHeight` (1.5 to 1.8, default 1.5, slider "sneak height" in `ViewmodelScreen`) is how far your own first person camera dips when sneaking. 1.5 is vanilla (eyes 1.62 to 1.27), 1.8 is no dip, in between is linear (`display/SneakHeight`). `CameraMixin` wraps the `getStandingEyeHeight` call in `Camera.updateEyeHeight` (the camera eases towards it, so the dip animation stays) only for the local player whose real pose is CROUCHING (`isInPose`, not `isInSneakingPose()`: `ClientPlayerEntity` overrides that with an input flag one tick behind the pose and eye height, which let vanilla's 1.27 through for one tick on every press, a visible dip even at 1.8; found 2026-10-11 from a camera log, pinned by `SneakHeightTest`); hitbox and the pose the server sees are untouched. Foecollab has no such setting. Checked in game 2026-10-11 at 1.8 and a middle value (l: works perfectly).
