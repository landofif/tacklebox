# Chat: filters, boxes, scrolling, copy

- Chat (`chat/`, `screen/ChatFilterScreen`, settings `chatFilters`/`chatPos`/`chatY`/`chatCopy`):
  - Hide rules run in `ALLOW_GAME` and `ALLOW_CHAT`, reusing `trigger/Matcher`.
  - `ChatHudMixin` moves the chat by wrapping the one `Backend.updatePose` call in `ChatHud.render(Backend,…)`. Drawing, hover and the `ChatScreen` click handler all go through it. Sideways the move is `chatPos` (stuck to the nearest side, see `../huds/positions.md`).
  - `chat/ChatCopy` finds the line under the mouse by running that same layout pass with its own `Backend` (via `ChatHudAccessor`); the same pass records each line's screen rectangle, and `ChatScreenMixin` fills the union of the hovered message's lines with a light background (like chatplus) with chat open. Copying says "tacklebox » message copied" in chat instead of a tag at the cursor.
  - The `/tacklebox` key is registered in `Tacklebox` (right shift, category `tacklebox:main`, names in `lang/en_us.json`).
- Chat boxes (`chat/ChatBox`, `chat/ChatBoxes`, `screen/ChatBoxScreen`, setting `chatBoxes`): `ChatHudMixin` hands each line to `ChatBoxes.route` at the top of `ChatHud.addMessage(Text, sig, indicator)`; a box that takes it keeps it (and logs it like vanilla, so latest.log still has every line). Boxes are hud elements after `VanillaHudElements.CHAT`; `ChatScreenMixin` scrolls them, shows hover text, and passes clicks to `ChatScreen.handleClickEvent`. Default rules (fishonmc only): dms `^✉ ?(from|to) `, crew `^\[crew chat\] ` (format from luna's memory, not seen in logs yet) and `^CREWS > ` (joins, leaves, missions, teleports; `Matcher.normalize` turns `»` into `>` before rules run, so rules are written with `>`). A saved crew box that still has only the old rule gets the crews rule on load (`ChatBoxes.addCrewsRule`); an edited one is left alone. `ChatFilterScreen` edits a box's rules when opened with a box.
- Chat box lines get the vanilla "text background opacity" strip (`ChatBoxes.draw`), luna asked 2026-10-08; the box itself stays transparent.
- Chat scrolling (2026-10-08, `chat/ChatBar` for vanilla chat, `ChatBoxes.draw` for the boxes): both ease to the scroll position (vanilla: `ChatHudMixin` runs `ChatHud.render(Backend,..)` with `scrolledLines` set to the whole line and restores the real target after, shifts the pose by the fraction and draws one extra line through `getVisibleLineCount`; boxes ease `State.shown` and clip to the lines area) and have a 5 px draggable scroll bar (vanilla's thin one is the 2nd and 3rd `Backend.fill` of that render, replaced by `ChatBar.draw`; dragging is polled in `ChatScreenMixin` render). Not run in game yet.
- Closing chat or sending a message scrolls vanilla chat (vanilla `removed` already did) and every box back to the newest line (2026-10-19, `ChatScreenMixin.tacklebox$toBottom`, `ChatBoxes.scrollToBottom`; the ease animates it). Not run in game yet.
- ctrl+F search (2026-10-19, `chat/ChatSearch`, luna asked for chatplus's behaviour; replaces the old `ChatSearchScreen`): ctrl+F in chat toggles search in place. What is in the chat box hides every message (vanilla chat and all boxes) that does not contain it, case-insensitive. Vanilla: `ChatHudMixin.tacklebox$searchHide` cancels `addVisibleMessage` for non-matches and `ChatHud.refresh()` rebuilds on every keystroke (`ChatScreenMixin` hooks `onChatFieldUpdate`); boxes skip hidden lines when wrapping (`ChatBoxes.refilter`). Enter does not send while searching, ctrl+F again clears the box and leaves, closing chat leaves too. A dim "search" hint shows above the box. No match highlighting. Not run in game yet.
- Chat stacking (`ChatHudMixin`, setting `chatStack`): a repeat of the newest line replaces it with "text (xN)".
- Chat boxes have no title row and no "nothing here yet" line (2026-10-10); an empty box draws nothing. The hud mover still names the highlighted box, above it. The `↓n` scroll marker is gone, the scroll bar shows position.
- Timestamps (`chat/ChatTimes`): hovering a message with chat open shows its arrival time as a tooltip, 24h `HH:mm:ss` local time, in the boxes and in vanilla chat. A message with its own hover text shows that instead. Boxes keep the time in their lines; vanilla chat keeps it by message object in `ChatTimes` (up to 2100 lines), recorded at the top of `ChatHud.addMessage`. Not run in game yet.
- Ctrl+A in chat replacing the text with an "a" was native Wayland GLFW (`UseNativeGLFW`), gone with the setting off in the Prism instance (2026-10-10). No code fix.
- Player chat loses the server's "!" in front of `[level]` and, with `chatTimeMode` (the "time" button in the chat filter screen cycles off, `[HH:MM:SS]`, `[HH:MM]`; off by default), every line starts with that gray stamp. Both happen in `ChatHudMixin` by `ChatTimes.rewrite`, which re-adds the rewritten message (guard `rewriting`), so chat boxes and stacking see the result (stacking compares without the stamp). Hide rules and triggers run earlier on the raw line and still see the "!". Hover time still shows with the stamp on. Not run in game yet.
- Hide huds behind chat (2026-10-19, setting `hideBehindChat`, off by default, toggle in settings > chat): `hud/HudCover` is asked by `HudPos.draw`, so the five huds that use `HudPos` (quests, level bars, boosts, now playing, server hud) are skipped while their last-drawn rectangle overlaps a visible chat box, the vanilla chat or the player list (only while the tab key is held). The vanilla chat and tab rectangles are estimates on the big side. The equipment row and the bobber text are not covered. Test: `HudCoverTest` (overlap only). Not run in game yet.
