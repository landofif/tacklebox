# Chat: filters, boxes, scrolling, copy

- Chat (`chat/`, `screen/ChatFilterScreen`, settings `chatFilters`/`chatPos`/`chatY`/`chatCopy`):
  - Hide rules run in `ALLOW_GAME` and `ALLOW_CHAT`, reusing `trigger/Matcher`.
  - `ChatHudMixin` moves the chat by wrapping the one `Backend.updatePose` call in `ChatHud.render(Backend,…)`. Drawing, hover and the `ChatScreen` click handler all go through it. Sideways the move is `chatPos` (stuck to the nearest side, see `../huds/positions.md`).
  - `chat/ChatCopy` finds the line under the mouse by running that same layout pass with its own `Backend` (via `ChatHudAccessor`). It counts which message on screen that line is and takes that one from `messages`, skipping messages ctrl+F search hides (they have no visible lines; before 2026-10-28 it did not skip them and copied a newer message while searching, test `ChatCopyTest`); the same pass records each line's screen rectangle, and `ChatScreenMixin` fills the union of the hovered message's lines with a light background (like chatplus) with chat open. Copying says "tacklebox » message copied" in chat instead of a tag at the cursor.
  - The `/tacklebox` key is registered in `Tacklebox` (right shift, category `tacklebox:main`, names in `lang/en_us.json`).
- Chat boxes (`chat/ChatBox`, `chat/ChatBoxes`, `screen/ChatBoxScreen`, setting `chatBoxes`): `ChatHudMixin` hands each line to `ChatBoxes.route` at the top of `ChatHud.addMessage(Text, sig, indicator)`; a box that takes it keeps it (and logs it like vanilla, so latest.log still has every line). Boxes are hud elements after `VanillaHudElements.CHAT`; `ChatScreenMixin` scrolls them, shows hover text, and passes clicks to `ChatScreen.handleClickEvent`. Default rules (fishonmc only): dms `^✉ ?(from|to) `, crew `^\[crew chat\] ` (format from luna's memory, not seen in logs yet) and `^CREWS > ` (joins, leaves, missions, teleports; `Matcher.normalize` turns `»` into `>` before rules run, so rules are written with `>`). A saved crew box that still has only the old rule gets the crews rule on load (`ChatBoxes.addCrewsRule`); an edited one is left alone. `ChatFilterScreen` edits a box's rules when opened with a box.
- Chat box lines get the vanilla "text background opacity" strip (`ChatBoxes.draw`), luna asked 2026-10-08; the box itself stays transparent.
- Chat scrolling (2026-10-08, `chat/ChatBar` for vanilla chat, `ChatBoxes.draw` for the boxes): both ease to the scroll position (vanilla: `ChatHudMixin` runs `ChatHud.render(Backend,..)` with `scrolledLines` set to the whole line and restores the real target after, shifts the pose by the fraction and draws one extra line through `getVisibleLineCount`; boxes ease `State.shown` and clip to the lines area) and have a 5 px draggable scroll bar (vanilla's thin one is the 2nd and 3rd `Backend.fill` of that render, replaced by `ChatBar.draw`; dragging is polled in `ChatScreenMixin` render). Not run in game yet.
- Closing chat or sending a message scrolls vanilla chat (vanilla `removed` already did) and every box back to the newest line (2026-10-19, `ChatScreenMixin.tacklebox$toBottom`, `ChatBoxes.scrollToBottom`; the ease animates it). Not run in game yet.
- ctrl+F search (2026-10-19, `chat/ChatSearch`, luna asked for chatplus's behaviour; replaces the old `ChatSearchScreen`): ctrl+F in chat toggles search in place. What is in the chat box hides every message (vanilla chat and all boxes) that does not contain it, case-insensitive. Vanilla: `ChatHudMixin.tacklebox$searchHide` cancels `addVisibleMessage` for non-matches and `ChatHud.refresh()` rebuilds on every keystroke (`ChatScreenMixin` hooks `onChatFieldUpdate`); boxes skip hidden lines when wrapping (`ChatBoxes.refilter`). Enter does not send while searching, ctrl+F again clears the box and leaves, closing chat leaves too. A dim "search" hint shows above the box. No match highlighting. Left click on a message while searching (2026-10-28) leaves the search, clears the box and scrolls that message to the middle with no easing (`ChatCopy.jumpTo` for vanilla, `ChatBoxes.jumpTo` for boxes, `ChatSearch.scrollToShow`); links in that message do not open on that click. Search, right click copy while searching and the left click jump checked in game by luna 2026-10-28 (vanilla chat and a box).
- Chat stacking (`chat/ChatStack`, setting `chatStack`, 2026-10-29 rework): a line that repeats one of the newest 20 messages, with numbers ignored (`12`, `1,234.50` all count as one number) and a `(xN)` at the end ignored, removes that older one and comes in at the bottom as "text (xN)" with the newest numbers. Time stamps are left out of the compare. Vanilla chat: `ChatHudMixin` removes the old message from `messages` and calls `refresh()`; boxes: `ChatBoxes.stack` on the box's own lines. Before 2026-10-29 only an exact repeat of the newest line stacked, and only in vanilla chat. Tests `ChatStackTest`, `ChatStackIntegrationTest`. Not run in game yet.
- Chat boxes have no title row and no "nothing here yet" line (2026-10-10); an empty box draws nothing. The hud mover still names the highlighted box, above it. The `↓n` scroll marker is gone, the scroll bar shows position.
- Timestamps (`chat/ChatTimes`): hovering a message with chat open shows its arrival time as a tooltip, 24h `HH:mm:ss` local time, in the boxes and in vanilla chat. A message with its own hover text shows that instead. Boxes keep the time in their lines; vanilla chat keeps it by message object in `ChatTimes` (up to 2100 lines), recorded at the top of `ChatHud.addMessage`. Not run in game yet.
- Ctrl+A in chat replacing the text with an "a" was native Wayland GLFW (`UseNativeGLFW`), gone with the setting off in the Prism instance (2026-10-10). No code fix.
- Player chat loses the server's "!" in front of `[level]` and, with `chatTimeMode` (the "time" button in the chat filter screen cycles off, `[HH:MM:SS]`, `[HH:MM]`; off by default), every line starts with that gray stamp. Both happen in `ChatHudMixin` by `ChatTimes.rewrite`, which re-adds the rewritten message (guard `rewriting`), so chat boxes and stacking see the result (stacking compares without the stamp). Hide rules and triggers run earlier on the raw line and still see the "!". Hover time still shows with the stamp on. Not run in game yet.
- Hide huds behind chat (2026-10-19, setting `hideBehindChat`, off by default, toggle in settings > chat): `hud/HudCover` is asked by `HudPos.draw`, so the five huds that use `HudPos` (quests, level bars, boosts, now playing, server hud) are cut off (luna 2026-10-20: only the overlapping part goes, not the whole hud) where their last-drawn rectangle overlaps a visible chat box, the vanilla chat or the player list (only while the tab key is held). The vanilla chat rectangle only counts lines still on screen (faded ones do not cover anything); it and the tab rectangle are estimates on the big side. The equipment row and the bobber text are not covered. Test: `HudCoverTest` (overlap and rectangle subtraction). Not run in game yet.
- Foecollab huds too (2026-10-20, luna's screenshot showed them overlapping): `hud/FoeCover` + `FoeHudsMixin` (fish tracker, pet, contest, bait, chummer, equipment, crew, quests, daily quests, level) and `FoeCustomHudsMixin` (each custom hud on its own) wrap foecollab's draw calls by name (optional, no descriptors, `@Coerce` receivers). A foecollab hud does not report its size, so `DrawContextTextMixin` adds up the text it draws (through the pose) into a rectangle; next frame the hud is drawn once per free piece with a scissor (`HudCover.clipped`) so only the overlapping part is cut off. Titles, notifications and the bobber timer are left alone. Checked in the dev client only that the mixins apply (no errors); not run in game yet.
- Empty box space no longer hides huds (2026-10-21, luna's screenshot: a crew box with two lines cut off huds in its whole rectangle): `HudCover` now counts a chat box by `ChatBoxes.contentRect`, only the bottom lines it draws (lines sit at the bottom), nothing when it has no line. Test `ChatBoxCoverTest`. Not run in game yet.
- Chat peek key (2026-10-29, `chat/ChatPeek`, key "peek at chat (hold)", unbound by default, in the tacklebox key category): holding it with no screen open makes vanilla chat and every box look like open chat (all lines, none faded, the open height, the scroll bar). Vanilla: `ChatHudMixin.tacklebox$peekRender` passes `focused` = true into the private `render(Backend,..)` from the public hud render (the hud backend stays, so no hover or clicks), and `tacklebox$peekFocused` wraps `isChatFocused` in `getHeight` and `addVisibleMessage` (open height; a new line keeps the place you scrolled to). `isChatFocused` itself is left alone: `InGameHud.renderChat` skips drawing when it is true. Boxes and `HudCover`: `ChatBoxes.chatOpen()` is true while peeking. The wheel scrolls only vanilla chat, 7 lines a notch, 1 with shift, like `ChatScreen` (`MouseMixin` cancels `Mouse.onMouseScroll` before `Scroller.update`, so the hotbar does not move; foecollab's `setSelectedSlot` redirect further down is untouched). The state updates each client tick (up to 50 ms late). Letting go or opening a screen scrolls vanilla chat and the boxes back to the newest line; opening chat while peeking keeps the place. Tests `ChatPeekTest`, `ChatPeekIntegrationTest`. Not run in game yet.
- One Escape closes chat (2026-10-29, luna asked): vanilla gives Escape to the command suggestions first, which only hide themselves. `ChatScreenMixin.tacklebox$escapeCloses` wraps `ChatInputSuggestor.keyPressed` in `ChatScreen.keyPressed` and skips it for Escape (`ChatKeys.toSuggestions`), so `Screen.keyPressed` closes chat. Vanilla's "Save Unsent Chats" still applies as for a normal Escape. Test `ChatKeysTest`. Not run in game yet.
- "here" + Tab (2026-10-29, `chat/ChatKeys`): Tab right after the word "here" (any case, a whole word) swaps it for `Kenai River (instance 3)`, or only the location outside an instance. Location from the boss bar (`ServerInfo.locationId`, names from `ServerInfo.LOCATIONS`), instance from the tab list footer `ɪɴꜱᴛᴀɴᴄᴇ <name> (` (field opened in `tacklebox.accesswidener`; digits only when there are any, like `compat/FoeButtons`). Only on fishonmc and with a location read; otherwise Tab does what it did. Not during ctrl+F search, not with shift. Tests `ChatKeysTest`, `hud/ChatHereIntegrationTest`. Not run in game yet; the footer format with a real instance has not been seen by tacklebox (taken from foecollab's `TabHandler`).
- Up arrow history after a restart or reconnect (2026-10-29, `chat/SentHistory`): vanilla keeps only commands in `command_history.txt` and, when it clears chat on disconnect (`ChatHud.clear(true)`), reloads only those. `ChatHudMixin` saves the whole history (messages and commands, newest 100) to `config/tacklebox/sent-history.txt` after each send and puts it back after the `ChatHud` constructor and after `clear(true)`. Before the first send with tacklebox, vanilla's command list stays. Tests `SentHistoryTest`, `SentHistoryIntegrationTest`. Not run in game yet.
- Half-typed message kept when chat closes: vanilla 1.21.11 already does it with Chat Settings > "Save Unsent Chats" (`saveChatDrafts`, off in luna's meowfih options on 2026-10-29). Kept until the game closes. No tacklebox code.
- Highlights (2026-10-29, `chat/ChatHighlight`, `screen/ChatHighlightScreen` from the "highlight" button in `/tacklebox chat`, settings `chatHighlightName` (on), `chatHighlights`): your name (the session username) in gold and each chosen word in its own colour, whole words, any capitals, longest word wins. Runs in `ChatHudMixin` right after `ChatTimes.rewrite`, before the boxes take a line, so vanilla chat and every box get it; hide rules and triggers ran earlier on the raw line, and the line's text does not change, so boxes, search and stacking compare the same words. Lines you sent (`name »`) are left alone. A word split over two differently styled pieces of a line is not found. Tests `ChatHighlightTest`, `ChatHighlightIntegrationTest`. Not run in game yet.
- Chat back after a reconnect or restart (2026-10-29, `chat/ChatRestore`, always on, fishonmc only): vanilla clears chat on disconnect (`InGameHud.clear` → `ChatHud.clear(true)`). `ChatHudMixin.tacklebox$saveChat` runs at the top of `ChatHud.clear` and writes the newest 200 vanilla lines and every box's lines (Text through vanilla's `TextCodecs.CODEC` with the registries from the last join, plus arrival time) to `config/tacklebox/chat-restore.json`; `CLIENT_STOPPING` saves too if nothing was saved since the join. On `JOIN`, an empty vanilla chat and empty boxes get the lines back (straight into `messages` / the box lines, so no hide rules, triggers, stacking, box routing or latest.log) with a dark gray `── 29 oct 14:32 ──` line (when it was saved) under them. Hover times keep the old times (`ChatTimes.record(text, millis)`). A reconfiguration keeps chat in vanilla already, so nothing is restored then (chat not empty). Boxes are not cleared on a reconnect inside one game, so they only get lines back after a restart. A line the codec cannot write is saved as plain words. Tests `ChatRestoreTest`, `ChatRestoreIntegrationTest` use a words-only codec, because vanilla's needs the game's registries and those do not start in plain unit tests (`Bootstrap.initialize` fails on an access error); colours and hover through the real codec are not tested. Not run in game yet.
