# Full text of the text and automation rules

- **Text is small capitals, like foecollab's labels.** luna first asked for no capital letters and no apostrophes (2026-10-02) and dropped that on 2026-10-06 ("ignore my note about everything being lowercased", sending foecollab's contest hud with its small caps labels and normal case values as the model). `Foe.text()` / `Foe.bold()` turn the letters of what the mod builds into Unicode small capitals (`Foe.smallCaps`, the same characters foecollab's `TextHelper.smallCaps` and the server use; digits and symbols stay) for labels, titles, headings and buttons. Tooltips and long descriptions use `Foe.sentence()` (normal font, first letter capital) because small caps are hard to read at length; debug output and chat messages the mod sends to you stay plain. Write literals in lowercase (the conversion lowercases first); apostrophes are allowed now, though older literals still say "dont". `Glyphs.menuName` stays lowercase on purpose, it is compared with menu names. foecollab's own labels in the settings keep their case (`FoeConfig.clean` no longer lowercases) and the search lowercases both sides.
- **The mediterranean sea is shown as "med", everywhere** (luna 2026-11-15: "just med", as foecollab already writes it in the compendium and the travel menu). The place in `menu/Locations.ALL` is named `med`, so every menu, tile, tooltip and screen that shows a place by its `name()` has it. Text that comes from the server (mini event missions, the boss bar's place in the server hud and the xp estimate, the frenzy and fabled place, the wrong gear lines) goes through `Locations.shown(text)` right where it is drawn. Never shorten a name that is matched: `ServerInfo.LOCATIONS`, `ServerInfo.locationName`, `GearCheck.PLACES`, a mission's `name` and the bait data keep the full name, and `Locations.byName` finds the place by its key `mediterranean`. The `here` chat key still types the full name, that text is sent to other players. The other places keep their names (the level bars and the event hud have their own one-word names in `LevelBars.SHORT`). Tests: `LocationsTest`, `MiniEventTest`, `GearCheckTest`, `FrenzyHudIntegrationTest`.
- **No automating the game.** (Replaces the "display only" rule, 2026-10-16: luna said it was only ever about not automating actions like fishing, selling or questing, and that other things are fine, like foecollab's bait sorter.) The mod never plays for the player: it does not cast, reel or run the fishing minigame, it does not sell, and it does not do quests or missions (no quest menu clicks, no turn-ins). Anything else is allowed, including sending commands, clicking and pressing keys, for example sorting items or opening menus. `fishonmc-autofish` stays a data source: none of its automation comes over. Gray areas luna did not name (auto `/pay` tips on REACTIONS, `/contest` refreshes, `/find` sends): ask luna before adding any.
- **Rebinding a key is not automation** (luna 2026-11-11, about the fish key, `keys/fish-key.md`): one key that is a right click with the rod and sneak while the minigame is on screen "just rebinds existing keys, it doesnt automate anything". The line it must not cross: every input is the player's own press, nothing is sent on a bite, on a timer or when the minigame ends, and holding the key never clicks again.
- **The mini event hud sends `/minievent` on a timer** (luna 2026-11-15, asked how it should get its numbers: "like FOE+"). The one allowed command on a timer: while the mini event hud is on, only on FishOnMC, every 10 minutes and a few seconds after a catch, with the answer hidden (`huds/mini-event.md`). It reads progress only; it does no mission for the player. Off sends nothing. This does not open the door for other timed commands: those are still gray areas to ask about.
- **History.** Until 2026-10-16 the rule was "display only": the mod only observed and rendered, with three exceptions, all asked for by luna and all only on the player's own click or key. They are still in the mod. Key commands (2026-10-06, `input/KeyCommands` + `screen/KeyCommandScreen`, setting `keyCommands`): a key or mouse button (middle, 4, 5; stored as 1000 + the glfw button) luna picked sends its command once per press, only with no screen open. The fishonmc menu screen (2026-10-06, `menu/FishMenu` + `screen/FishMenuScreen`) replaces the chest gui for the main menu and /travel and forwards the player's own click on a button as a slot click. The vault overview (2026-10-08, `menu/Vaults`) sends `/pv n` when another vault is clicked. Code comments that say "display only" describe what that one class does (it changes no item and sends nothing), not a project rule.
