# FOECollab tweaks: lure sorting, buttons, pet memory

- Lure sorting (2026-10-08, `mixin/BaitSortingHelperMixin` + `compat/FoeLureSort`): foecollab's bait sorting helper only squares up identical baits; at the head of its `renderItemMarker` we do the same for lures with the same name and every lore line except the one containing "uses" (colour and size are only known from the tooltip, no lure NBT dump yet, so the key is the lore). Active exactly when foecollab's helper is (its config and key, by reflection). `KeybindHandlerMixin` makes its bait sorting key a toggle (each press flips it, state kept while screens close). Not run in game yet.
- Instance in inventory buttons (2026-10-08, `mixin/InventoryScreenHandlerMixin` + `compat/FoeButtons`): `{instance}` in the name, description or icon of one of foecollab's custom inventory buttons (its Inventory Button Editor) is swapped for the instance number (foecollab's `TabHandler.instance`) while the button is built when the inventory opens, then put back so the saved button keeps the placeholder. The editor itself is foecollab's and does not mention it. Not run in game yet.
- Pet hud memory (2026-10-08, `mixin/PetEquipHandlerMixin` + `compat/FoePet`): foecollab's `PetEquipHandler` only trusts its login scan (the pet in the saved slot and its entity seen within 5 s of loading), else logs "[FoE] Did not find Pet" and the hud says no pet until a re-equip. At the end of its tick we look, every second, for the pet it saved (`profileData.equippedPet.id`) anywhere in the inventory when it says NO_PET but a saved pet and slot exist (a real unequip clears both), and put it back (status, item, slot). By reflection. Not run in game yet.
- **Daily mission tracker (2026-10-11):** foecollab's `DailyQuestHandler.tick` parses each lore line of the Daily Missions item alone and wants `| goal (p/n)`; the update split name and progress over two lines, so its tracker went empty. `mixin/DailyQuestHandlerMixin` (by name, `tick` TAIL, `require = 0`) calls `compat/FoeDailyMissions.fill`, which, when foecollab's list is still empty, reads the new layout off the open menu's item and adds the unfinished missions through reflection (`Quest(String,int,int,int)`); finished ones (✔) are skipped like foecollab does. Live progress: foecollab counts by goal text through `DailyQuestHandler.updateQuest(String)` (`Quests Completed` and `Contest Participation` from chat, `Shards Caught`, `Total Caught`, `Mythical Caught` from its catch handler). The mixin also renames `Total Caught` to `Anywhere` and `Mythical Caught` to the `U+F037` glyph (`FoeDailyMissions.renameGoal`), and `FoeCatch.onCatch` calls `updateQuest` with the fish's display name for the species missions (Lumpfish, Opah...). Assumption: a species mission counts that fish wherever it is caught; opening the menu re-reads the true numbers anyway. Tests: `FoeDailyMissionsTest` (real dump lines). Not run in game yet: the tracker hud showing the missions after opening /menu, and whether the glyph named mission looks right in it.
  - Hud look (2026-10-11): `mixin/DailyQuestTrackerHudHandlerMixin` (`buildQuestText` RETURN) calls `FoeDailyMissions.styleLines`, which rewrites foecollab's quest lines in the tooltip colours (green name, yellow progress, light blue goal `0x7FB8FF`, a guess from a screenshot) and adds a small caps header line ("Base Missions", "Lofoten Islands Missions") when the section changes; the section of each goal is remembered from the last menu read (`sectionOf`). Done and not started quests keep foecollab's line. Not seen in game yet.
