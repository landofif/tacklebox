# FOECollab integration

- **FOECollab is optional (2026-10-30).** `fabric.mod.json` only suggests it. Every mixin into foecollab lives in `foemixin/` and `tacklebox.foecollab.mixins.json`, whose plugin `compat/FoeMixinPlugin` applies them only when `FoeCollab.loaded()` (fabric loader says `foecollab` is installed). Calls from tacklebox code into `compat/` either check `FoeCollab.loaded()` or fail quietly (reflection caught). Without foecollab: `Foe.box` draws a plain see-through rounded box instead of foecollab's box texture, the server hud's tackle shop and moon cycle lines (foecollab's TimerHandler) do not show, `/tacklebox huds` is not registered. `FoeCollabOptionalIntegrationTest` checks no main-config mixin targets foecollab. Checked 2026-10-30: a dev client without the foecollab jar reaches the title screen with no mixin errors. Not run on the server without foecollab yet.

- **Dev client and foecollab hooks:** in a dev run foecollab keeps intermediary names while vanilla is yarn, so string mixins with intermediary descriptors do nothing there; hooks on methods without overloads use the bare method name (see memory foecollab-hooks).
- **The huds go in foecollab's hud mover.** `MoveHudScreenMixin` targets `io.github.foecollab.screens.movehud.MoveHudScreen` by name (no compile dependency), injects at the return of its private `renderWidgets` (its own method name survives the release jar; `require = 0` so a foecollab update that renames it only loses the boxes) and `compat/FoeMover` adds a drag box for the quests left hud, the default chat and every chat box (right click puts one back, scroll resizes a chat box). While the mover is open the mods huds skip their normal draw so they show once. `FoeScreens.openMover` opens it from our screens.
- FOECollab (`compat/`): `FoeScreens` opens its screens by class name and reflection (hud mover, menu, custom hud editor). `FoeMover` + `MoveHudScreenMixin` are the hud mover link above. Nothing of it is compiled against.
  - Both mods touch some of the same vanilla calls. Never `@Redirect` a call FOECollab also redirects (it crashes at load); use `@WrapOperation`. FOECollab redirects `Bar.drawExperienceLevel` in `InGameHud.renderMainHud`, `BossBarHud.render`, `Mouse.onMouseScroll`, `ClientPlayerInteractionManager.clickSlot` and parts of `PlayerListHud`.
  - Dev runs: drop a FOECollab jar and its nested `META-INF/jars/*` (proxlib, DiscordIPC) in `run/foecollab/` (gitignored, picked up by `modLocalRuntime`). Its huds only draw on fishonmc (`LoadingHandler.isOnServer`).
- Huds: the mod has no hud system of its own (removed 2026-10-06, luna likes foecollab's custom huds more). `FoeScreens.customHuds` opens foecollab's editor from /tacklebox. The mods own boxes (quests left, chat boxes) are drawn in the `custom_huds` and `chat_boxes` hud elements with no box and moved in foecollab's mover (above).
