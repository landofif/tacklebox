# Chummer range ring (built 2026-10-17, not run in game yet)

- What it does: draws a thin flat ring on the ground at the range of every placed chummer the client knows about, not only the one you stand in. Built from scratch for luna (2026-10-16: FOECollab's chummer tracker "looks and seems weird" to her; her own foecollab config has its chummer hud and ring off, `showChummerHud=false`, `solidRangeBar=false`, `rangeRadius=20`). It shares no code with foecollab and does not touch it. Display only, no mixins, no hud row and no change to the boosts hud (luna's call for now).
- Settings (world page, tile "chummer"): `chummerRing` (toggle, default on) and `chummerRingColor` (rgb, default `0x41F55B`, the green the server uses for `Bite Speed:` in the hologram). The alpha is fixed (`ChummerRingGeometry.ALPHA`, 0xA0).
- Files (all in `display/`):
  - `ChummerText`: pure string parser, `parse(text)` returns `Optional<Chummer(owner, bite, rarityGlyph, seconds)>`. Server glyphs (private use and hangul, `Glyphs.isArt`) and `§` codes are stripped from every line before matching; the rarity glyph is read from the raw line between the first line and the owner line. `bite` and `seconds` are -1 when their line is missing, `rarityGlyph` is 0 without a glyph, `rarity()` names `U+F033` to `U+F037` (common, rare, epic, legendary, mythical). Time formats: any mix of `h`, `m`, `s` parts before `Remaining` (`14m 55s`, `55s`, `15m`, `1h 2m 3s`).
  - `ChummerRingGeometry`: pure numbers, no Minecraft classes. `RADIUS` 20, `WIDTH` 0.2 (centred on the radius, so 19.9 to 20.1), 128 segments, `ringY(textY)` = `textY - 2.0 + 0.02`, `inRange(chummerX, chummerZ, x, z)` (horizontal, <= 20), `argb(rgb)`, `emit(cx, y, cz, sink)` (the 128 quads, four corners each, going round the band).
  - `ChummerRing`: `tick` (called from the end client tick) scans `world.getEntities()` for `TextDisplayEntity` every 10 ticks and keeps the x, y, z of each one `ChummerText.parse` accepts; `register()` hooks `WorldRenderEvents.AFTER_ENTITIES`, which draws a `RenderLayers.debugQuads()` ring (cull off) for each, camera-relative (`ctx.worldState().cameraRenderState.pos`, see `WorldRenderContext#consumers`). The draw only reads the positions saved by the scan, as the Fabric docs ask (nothing outside the render state in the render event). `Tacklebox` calls `register()` at start, `tick` every tick and `reset()` on disconnect. Switching the setting off drops the list at once; switching it on scans at once.
- How it finds a chummer: only the hologram text counts (first non-blank line `Chummer™` plus an `Activated by <name>` line). Never the head: `player_head` item displays with the same look are everywhere as decoration, and the nameplate of a player or a pet name (`Vondopolous Ablehower II`) has no such first line.
- Gotchas:
  - **The ring lands exactly on the ground.** luna's dump: hologram y 27.98, ground (her feet) 26.0, so `27.98 - 2.0 + 0.02` is 26.00, level with the top of the block. `RenderPipelines.DEBUG_QUADS` is the plain position+colour pipeline with culling off and no depth offset (bytecode, build.3), so a ring level with the ground may shimmer or break up into dashes. If that shows in game, raise `ChummerRingGeometry.LIFT` (0.05 or so) and note it here. Not seen yet because it was never run.
  - A chummer that expires stays drawn for up to 10 ticks (the scan interval); a newly placed one appears up to 10 ticks late.
  - The band is only 0.2 wide and 20 blocks from the middle, so it is thin at a distance on purpose.
  - Nothing uses `inRange` yet; it is there for a hud row ("in range of a chummer") if luna wants one, and for the tests.
- Tests: `ChummerTextTest` (the real dump text, every rarity glyph, the other holograms of the dump and a player nameplate rejected, time formats, missing lines, glyph stripping), `ChummerRingGeometryTest` (flat, closed band, area, corner distances, ringY from the dump, range, colour), `ChummerRingIntegrationTest` (settings json: old settings get it on in green, a saved choice round trips; dump text to parsed chummer to the ring's corners against `inRange`). Not covered, needs the game: the scan on real entities and the drawing itself.
- To check in game: the ring shows in the right place (centred on the hologram's x and z, on the ground), is 20 blocks from the middle to the edge (luna measured 20.05 to the server's own particle circle, so it may sit a hair inside it), is not shimmering, shows for a chummer placed by someone else and one further than render distance, and goes away when the chummer expires or the toggle is off; the colour picker changes it live.

## What a placed chummer is (research)

- Range: 20 blocks horizontally, measured by luna from the centre (-1523.533 63 2018.497) to an edge (-1503.483 64 2018.643), 20.05 blocks. All new chummers have 20; some players still hold about year-old ones with 10 (the lore says `Range of 10 blocks`, `custom_data` has no range). Decision: assume 20.
- Item: `player_head`, `custom_data {bitespeed, rarity, timer:15.0f, type:"chummer"}`; bite speed by rarity 75, 130, 180, 250, 375. The server answers `Place the Chummer on a block.` when you use it off a block and refuses a second chummer nearby.
- luna's dump 2026-10-17 (`entities-20261017-011501.txt`, 2.5 blocks away): two display entities at the same block centre x and z (`-810.5`, `1065.5`). An `item_display` at y 27.48 (luna stood at 26.0, so about 1.5 above the ground) holding a `player_head` named `Chummer` with a fixed skin texture (url hash `7a257396...`, no `custom_data`), scale 1.2, billboard fixed. A `text_display` 0.5 higher (y 27.98, billboard vertical) whose lines are `Chummer™`, the rarity tag glyph (`U+F033` is common), `Activated by <name>`, a blank line, `Bite Speed: +75` and `14m 55s Remaining`, counted down by the server. So owner, bonus, rarity and the exact time left can all be read client-side from that text, and display entities are tracked far beyond render distance.
- FOECollab never finds any of this: it takes the placer's name from the chat line, then the spot the placer is looking at (raycast 6 blocks, else their feet), so placers outside render distance are ignored. It draws a translucent wall 1 block tall (96 segments, `WorldRenderEvents.AFTER_ENTITIES`, `RenderLayers.debugQuads()`) and its own comments say the server draws a particle circle too. Whether that particle circle also shows was not looked at.
- Unknown: the exact rule for the ground height under a chummer (one sample), and whether the server's particle circle is drawn on top of the ring.
- The entity dump that found this: `/tacklebox debug entities [radius]` (`DebugDump.entities`, default 24, max 64) writes the crosshair target, every entity and every block entity around you to `config/tacklebox/guidump/entities-<time>.txt` and the clipboard; see `dev/build-and-debug.md`.
