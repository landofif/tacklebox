# Chummer range wall (built 2026-10-17, reworked the same day, not run in game yet)

- What it does: draws a one block high wall standing on the ground at the range of every placed chummer the client knows about, not only the one you stand in. Built from scratch for luna (2026-10-16: FOECollab's chummer tracker "looks and seems weird" to her; her own foecollab config has its chummer hud and ring off, `showChummerHud=false`, `solidRangeBar=false`, `rangeRadius=20`). It shares no code with foecollab and does not touch it. Display only, no mixins. The active boosts hud lists every detected chummer (2026-10-18, see below).
- Settings (fishing page, group "chummer"): `chummerRing` (toggle, default on) and `chummerRingColor` (rgb, default `0x41F55B`, the green the server uses for `Bite Speed:` in the hologram). The alpha is fixed (`ChummerRingGeometry.ALPHA`, 0xA0).
- Files (all in `display/`):
  - `ChummerText`: pure string parser, `parse(text)` returns `Optional<Chummer(owner, bite, rarityGlyph, seconds)>`. Server glyphs (private use and hangul, `Glyphs.isArt`) and `§` codes are stripped from every line before matching; the rarity glyph is read from the raw line between the first line and the owner line. `bite` and `seconds` are -1 when their line is missing, `rarityGlyph` is 0 without a glyph, `rarity()` names `U+F033` to `U+F037` (common, rare, epic, legendary, mythical). Time formats: any mix of `h`, `m`, `s` parts before `Remaining` (`14m 55s`, `55s`, `15m`, `1h 2m 3s`).
  - `ChummerRingGeometry`: pure numbers, no Minecraft classes. `RADIUS` 20, `HEIGHT` 1.0, `LIFT` 0.02, 128 segments, `fallbackY(textY)` = `textY - 2.0 + 0.02` (only when no ground is found), `inRange(chummerX, chummerZ, x, z)` (horizontal, <= 20), `argb(rgb)`, `emit(cx, y, cz, sink)` (`y` is the bottom; 128 upright quads, four corners each, going round the wall).
  - `ChummerRing`: `tick` (called from the end client tick) scans `world.getEntities()` for `TextDisplayEntity` every 10 ticks and keeps the x, z and the ground y of each one `ChummerText.parse` accepts (`groundY`: top of the first block with a collision shape within 6 blocks below the hologram, plus `LIFT`, else `fallbackY`); `register()` hooks `WorldRenderEvents.AFTER_ENTITIES`, which draws a `RenderLayers.debugQuads()` wall (cull off) for each, camera-relative (`ctx.worldState().cameraRenderState.pos`, see `WorldRenderContext#consumers`). The draw only reads the positions saved by the scan, as the Fabric docs ask (nothing outside the render state in the render event). `Tacklebox` calls `register()` at start, `tick` every tick and `reset()` on disconnect. The scan runs whatever `chummerRing` says (the active hud needs it); the setting only gates the drawing.
  - Active hud (2026-10-18, asked for by luna: it only showed the chummer whose chat line you saw, i.e. one placed while you were there): `ChummerRing.detected()` gives `Detected(owner, bite, endMs)` for every parsed hologram, `BoostsHud.rows()` adds a row `chummer +75 <owner>` with the hologram's time left. When any is detected the chat-based row is skipped (it is the same chummer); with none detected the chat row stays as the fallback. Time is the hologram's, refreshed every scan. Not run in game yet.
- How it finds a chummer: only the hologram text counts (first non-blank line `Chummer™` plus an `Activated by <name>` line). Never the head: `player_head` item displays with the same look are everywhere as decoration, and the nameplate of a player or a pet name (`Vondopolous Ablehower II`) has no such first line.
- Gotchas:
  - **The hologram bobs up and down by default (luna, 2026-10-17)**, although the single dump shows it still at 27.98. The first version took the ring height from the hologram's y, so the ring moved with it. The wall now stands on the ground found under the hologram, which does not move. Not seen in game yet.
  - `RenderPipelines.DEBUG_QUADS` is the plain position+colour pipeline with culling off and no depth offset (bytecode, build.3), so the bottom edge may still shimmer against the ground; `LIFT` (0.02) is there for that, raise it if it shows.
  - A chummer that expires stays drawn for up to 10 ticks (the scan interval); a newly placed one appears up to 10 ticks late.
  - The wall has no thickness, so seen exactly edge-on along its length it is a line; any other angle shows its full height.
  - Nothing uses `inRange` yet; it is there for a hud row ("in range of a chummer") if luna wants one, and for the tests.
- Tests: `ChummerTextTest` (the real dump text, every rarity glyph, the other holograms of the dump and a player nameplate rejected, time formats, missing lines, glyph stripping), `ChummerRingGeometryTest` (one block high on the given ground, closed wall, corners on the range, fallback from the dump, range, colour), `ChummerRingIntegrationTest` (settings json: old settings get it on in green, a saved choice round trips; dump text to parsed chummer to the ring's corners against `inRange`). Not covered, needs the game: the scan on real entities, the ground lookup and the drawing itself.
- To check in game: the wall stands in the right place (centred on the hologram's x and z, on the ground) and stays still while the hologram bobs, is 20 blocks from the middle to the edge (luna measured 20.05 to the server's own particle circle, so it may sit a hair inside it), is not shimmering, shows for a chummer placed by someone else and one further than render distance, and goes away when the chummer expires or the toggle is off; the colour picker changes it live.

## What a placed chummer is (research)

- Range: 20 blocks horizontally, measured by luna from the centre (-1523.533 63 2018.497) to an edge (-1503.483 64 2018.643), 20.05 blocks. All new chummers have 20; some players still hold about year-old ones with 10 (the lore says `Range of 10 blocks`, `custom_data` has no range). Decision: assume 20.
- Item: `player_head`, `custom_data {bitespeed, rarity, timer:15.0f, type:"chummer"}`; bite speed by rarity 75, 130, 180, 250, 375. The server answers `Place the Chummer on a block.` when you use it off a block and refuses a second chummer nearby.
- luna's dump 2026-10-17 (`entities-20261017-011501.txt`, 2.5 blocks away): two display entities at the same block centre x and z (`-810.5`, `1065.5`). An `item_display` at y 27.48 (luna stood at 26.0, so about 1.5 above the ground) holding a `player_head` named `Chummer` with a fixed skin texture (url hash `7a257396...`, no `custom_data`), scale 1.2, billboard fixed. A `text_display` 0.5 higher (y 27.98, billboard vertical) whose lines are `Chummer™`, the rarity tag glyph (`U+F033` is common), `Activated by <name>`, a blank line, `Bite Speed: +75` and `14m 55s Remaining`, counted down by the server. So owner, bonus, rarity and the exact time left can all be read client-side from that text, and display entities are tracked far beyond render distance.
- FOECollab never finds any of this: it takes the placer's name from the chat line, then the spot the placer is looking at (raycast 6 blocks, else their feet), so placers outside render distance are ignored. It draws a translucent wall 1 block tall (96 segments, `WorldRenderEvents.AFTER_ENTITIES`, `RenderLayers.debugQuads()`) and its own comments say the server draws a particle circle too. Whether that particle circle also shows was not looked at.
- Ported to FOECollab (2026-10-29, branch `chummer-hologram-tracker` on landofif/FOECollab, from Kimberlyow's 3.1.3, no PR yet, luna says when): `ChummerHandler` reads the hologram with `ChummerHologram` (this parser) every 10 ticks instead of the chat line, its hud gets the real timer and the floating head as icon, `ChummerRangeRenderer` draws this wall (`ChummerRingGeometry`, foecollab's `barColor`, alpha 0xA0), `rangeRadius` removed (fixed 20). 25 tests. Not run in game yet.
- Unknown: the exact rule for the ground height under a chummer (one sample), and whether the server's particle circle is drawn on top of the ring.
- The entity dump that found this: `/tacklebox debug entities [radius]` (`DebugDump.entities`, default 24, max 64) writes the crosshair target, every entity and every block entity around you to `config/tacklebox/guidump/entities-<time>.txt` and the clipboard; see `dev/build-and-debug.md`.
