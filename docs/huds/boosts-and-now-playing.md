# Active boosts and now playing huds

- Active boosts hud (2026-10-09, asked for by luna as its own hud, chat lines only because the boss bar and scoreboard are unreliable; `hud/BoostsHud`, settings `boostsHud/boostsPos`, "active boosts" in the cloth tab, a mover box): text with a shadow and no box like quests left. Rows: player boosters (`BOOSTER » x has activated a Global Luck Booster » 2x for 30m!`, exact countdown from the length in the line, removed by the `has expired` line, kept across disconnects because they are global and lost on a game restart), every chummer whose hologram the client tracks (`ChummerRing.detected()`, row `chummer +75 owner` with the hologram's time left, so ones placed before you arrived show too; see `chummer-range.md`), and when none is tracked the chat-line chummer (no length in the line, 15 min: the item says `Lasts for 15 minutes` and the run-out line comes about 15:00 later in the logs, removed by `Chummer has run out of stock`, one slot), then the weather events and moon that `ServerHud` tracks (`activeEvents`/`activeMoon`, with the bonus shown, no countdown because the end lines say it). The fish frenzy (2026-10-10, `BoostsHud`, parsing in `EventLines`) is a row `fish frenzy <place>` with a countdown from the alert's 1 hour, corrected by each reminder line, removed by the end line; the server hud has its own `fish frenzy` line from the fixed cycles (see `server-hud.md`). The fabled event is a row `Fabled Event at <place>` with no timer (it ends when someone catches the fish); `ServerHud.onChat` reads its header line and the line under it. The server hud still shows its own weather and moon lines unless switched off in its line list. Formats in the research doc. Not run in game yet.
  - Colours (2026-10-28, luna: "like in chat"): each row shows its words in the colours its chat line gave them, read when the line arrives (`util/ChatColors.of(line, words)`: the colour of the words' first letter in the line as sent, else of their first word, because the words come from the normalized line, which drops glyphs and turns » into >). Boosters: the type (`Event booster`) and the multiplier (`2x`). Weather: the name (the line's noun like `Thunderstorm`, else its tag) and the bonus (`+100 Bite Speed`; gold rush's `Shards → 1 in 25` takes the colour of `Base Shard Chance`). Moon: the name as the line writes it (`A Full Moon has risen`; there is no fallback to the `FULL MOON` tag, every moon line in the logs has the name) and the bonus. Fabled event: the header's `FABLED` and the place. Fish frenzy: `Fish Frenzy` (the alert's `Fish at X` line only has `Fish`) and the place. A chummer from chat: its bonus. A chummer from its hologram: the hologram's `Bite Speed:` green `#41F55B`, owner white. Timers stay white, the heading is unchanged, and words the line gave no colour stay grey (white on the right) as before. `ServerHud` keeps the two colours after its own fields in each event entry and hands `BoostsHud.Row`s out; its own weather lines still use its fixed table. `ServerHud.IMAGE` became `ServerHud.image()` so the class loads in unit tests. Tests: `ChatColorsTest`, `BoostsHudColorsTest` (the hologram chummer row sets `ChummerRing`'s private `detected` list by reflection, only `ChummerRing.tick` fills it in game), `BoostsColorsIntegrationTest` (luna's screenshot lines through both chat handlers to the drawn small capitals) and the frenzy row in `FrenzyHudIntegrationTest` (a frenzy line elsewhere would leave its "last seen" time behind for it). The colours in the tests are close to the screenshots, not read from the server. Not run in game yet.
- Now playing hud (2026-10-09, asked for by luna; `hud/NowPlaying`, settings `nowPlaying/nowPlayingPos` and one toggle each for `nowPlayingHeading/Art/Artist/Bar/Time` (the title is always shown), "now playing" in the cloth tab, a mover box): title, artist, `m:ss / m:ss`, a 2 px progress bar and the cover of whatever plays on the computer (spotify, youtube in a browser, any MPRIS player), text with a shadow and no box like the boosts hud, shown everywhere, not only on fishonmc. A daemon thread runs `playerctl -a metadata --format ...` once a second (fields split by U+001F) and takes the first playing player, else the first paused one ("paused" before the time). The cover is `mpris:artUrl` (http, https or file), fetched once per url by a `CompletableFuture`, decoded with LWJGL's `STBImage` directly (`NativeImage.read` checks the PNG signature and covers are jpeg: the stb pixels are wrapped with the `NativeImage(Format, w, h, true, pointer)` constructor like vanilla does), the middle square is scaled to 128 px with `resizeSubRectTo` (the sampler is only bilinear), handed to the render thread through an `AtomicReference` and registered with `MenuBackground.smooth`; the room for it is kept while it loads and dropped if the url fails. Linux only and needs `playerctl` on PATH: without it the thread logs once and stops, the hud stays empty. No play/pause/skip controls (the display-only rule that barred them was dropped 2026-10-16, so they can be added if luna asks). Decode, crop and resize were run outside the game against the real `NativeImage` with a 16:9 jpeg; the drawing is not run in game yet.
