# Active boosts and now playing huds

- Active boosts hud (2026-10-09, asked for by l as its own hud, chat lines only because the boss bar and scoreboard are unreliable; `hud/BoostsHud`, settings `boostsHud/boostsX/boostsY`, "active boosts" in the cloth tab, a mover box): text with a shadow and no box like quests left. Rows: player boosters (`BOOSTER » x has activated a Global Luck Booster » 2x for 30m!`, exact countdown from the length in the line, removed by the `has expired` line, kept across disconnects because they are global and lost on a game restart), the chummer (no length in the line, 15 min assumed from the logs, removed by `Chummer has run out of stock`, one slot), then the weather events and moon that `ServerHud` tracks (`activeEvents`/`activeMoon`, with the bonus shown, no countdown because the end lines say it). The server hud still shows its own weather and moon lines unless switched off in its line list. Formats in the research doc. Not run in game yet.
- Now playing hud (2026-10-09, asked for by l; `hud/NowPlaying`, settings `nowPlaying/nowPlayingX/Y` and one toggle each for `nowPlayingHeading/Art/Artist/Bar/Time` (the title is always shown), "now playing" in the cloth tab, a mover box): title, artist, `m:ss / m:ss`, a 2 px progress bar and the cover of whatever plays on the computer (spotify, youtube in a browser, any MPRIS player), text with a shadow and no box like the boosts hud, shown everywhere, not only on fishonmc. A daemon thread runs `playerctl -a metadata --format ...` once a second (fields split by U+001F) and takes the first playing player, else the first paused one ("paused" before the time). The cover is `mpris:artUrl` (http, https or file), fetched once per url by a `CompletableFuture`, decoded with LWJGL's `STBImage` directly (`NativeImage.read` checks the PNG signature and covers are jpeg: the stb pixels are wrapped with the `NativeImage(Format, w, h, true, pointer)` constructor like vanilla does), the middle square is scaled to 128 px with `resizeSubRectTo` (the sampler is only bilinear), handed to the render thread through an `AtomicReference` and registered with `MenuBackground.smooth`; the room for it is kept while it loads and dropped if the url fails. Linux only and needs `playerctl` on PATH: without it the thread logs once and stops, the hud stays empty. Display only, no play/pause/skip controls (they would break the display-only rule). Decode, crop and resize were run outside the game against the real `NativeImage` with a 16:9 jpeg; the drawing is not run in game yet.
