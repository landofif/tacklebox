# Hud and chat box positions

- Why (2026-10-11, l): the huds were saved as a fixed pixel offset from the top left, so F11, a tiled window or a split screen moved them, and one placed at the right edge ended up cut off or gone. Now each one keeps its distance to the nearest sides of the window.
- `hud/HudPos` (plain ints, unit tested): per axis the gap to the nearest side (left or right, top or bottom) plus which side. A hud stuck to the right or bottom keeps its own far edge at that gap, so it stays put when its width changes (the level hud's width follows the location name). `left(sw)` / `top(sh)` give where to draw and always push it back inside the window (not saved), `moveTo` pins it to the nearest sides from a dragged corner, `measure` remembers the size the last draw had (the far edges need it), `draw` does both around a hud's draw call. Numbers are gui pixels, hud scale included.
- Settings: `questsPos`, `levelBarsPos`, `boostsPos`, `nowPlayingPos`, `serverHudPos` (one `HudPos` each), `ChatBox.pos` per chat box, `chatPos` for the vanilla chat. The old `*X` / `*Y` of the five huds are only the spot drawn this frame (each hud's `draw` sets them from its pos, the drawing code still reads them); never edit them.
- Old settings: a `HudPos` made from old numbers is not `pinned`; the first draw (when the size is known) reads them as a plain top left corner in the current window and pins them to the nearest sides. `DofiSettings.sanitize` makes the pos of the five huds and the vanilla chat from `*X/*Y`, `ChatBoxes.rect` makes a box's from its percent `x`/`y`. So the first start after the update should be in the usual window (fullscreen): started in a small window the huds get pinned to that window's edges.
- Mover (`compat/FoeMover`): dragging calls `moveTo`, right click makes a fresh `HudPos` with the default corner, edge drags on a chat box and on the vanilla chat pin again from the new size so the edge you hold stays under the mouse. Scaling a hud with the wheel keeps its pinned edges (a right or bottom hud grows towards the middle).
- Vanilla chat: only sideways. `chatPos.x` is the gap to the left or right edge (width from `ChatBar.width()`, the game's own chat options); up and down it was already an offset from the bottom (`chatY`) and stays that. `chatX` is only read once, to make the pos.
- Not covered: the bobber timer and the bite alert (percent of the window, centred text), the hotbar and equipment row (offsets from the bottom middle).
- Tests: `HudPosTest`, `HudPositionsIntegrationTest` (l's old settings.json numbers through load, first draw, save and load in other window sizes), `ChatBoxesTest` (boxes at the right and bottom edge, open chat grows upward).
- Checked in game 2026-10-11 (l): the huds stay put through F11, a plain window and a split screen. Not confirmed yet: the dms and crew boxes, edge resizing of a chat box, and the vanilla chat dragged to the right half.
