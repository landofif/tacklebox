# Bobber timer and bite hud

- Bobber timer (2026-10-08, asked for by luna because foecollab's is disliked; `display/BobberTimer`, `screen/BobberScreen`, `/tacklebox bobber`, settings `timer*`/`bite*`): the timer is the own bobber's `age`, as a hud (`custom_huds`, mover box) and/or text over the bobber (projected to the screen and drawn in the hud, `BobberTimer.drawOverBobber`, because world text is flushed with the models and a hat covered it); the bite notification is a hud fed by the server's BITE! title (`InGameHudOverlayMixin.setTitle`, re-sends within 1.5 s are the same bite), with animation, duration, size, colour, shadow, text. `MinecraftClientMixin.doItemUse` marks the bobber as reeled on a right click with the rod, which hides the hud timer and the bite at once (the text over the bobber follows the bobber). The foecollab timer/bite title are left to be turned off in its own config. Not run in game yet.

- Focus window on bite (2026-10-19, luna's idea, `display/BiteFocus`, setting `biteFocus`, off by default, toggle on `screen/BobberScreen`): on the BITE! title the mod runs `hyprctl dispatch "hl.dsp.focus({ window = 'initialtitle:^Minecraft.*' })"` (Hyprland only; the Prism game window has an empty class, so it matches by `initialtitle:^Minecraft.*`, not `title:`, because a browser tab titled "Minecraft ..." matched too and got focused instead (2026-10-21); 0.56 takes Lua in dispatch, the old `focuswindow title:..` form is a syntax error, and the regex must match the whole title), at most once per 2 s, and not at all while the game window already has focus (Hyprland warps the cursor to the window centre on every focus dispatch, which yanked the cursor mid-click, 2026-10-28; not seen in game yet). It only focuses and stays there; it sends no input, so casting and reeling stay with the player. Runs even when the bite notification is off. Not run in game yet; the command was tried by hand on the live desktop and focuses the game window, the bite trigger is not seen in game yet.

- Bite countdown (2026-10-21, ported from fishutils' bite timer; `display/BiteCountdown`, `mixin/ClientPlayNetworkHandlerParticleMixin`, setting `timerStyle` UP/COUNTDOWN, default UP, "style" button on `screen/BobberScreen`): in COUNTDOWN style the timer (hud and over the bobber, same size/colour/decimals/unit) shows the predicted seconds until the bite, only while a fish approaches. Once a fish swims toward the bobber the server sends a `minecraft:fishing` particle (count 0) per tick at a distance from the bobber that shrinks to 0 at the bite. `BobberTimer.onParticle` keeps only the ones within 10 blocks whose line to a bobber is most perpendicular to the particle's sideways speed (|cos| < 0.30) and where that bobber is your own, so a neighbour's fish is ignored. `BiteCountdown` needs 4 inward particles in a row, measures the inward speed over the last 1.2 s (clamped 0.5 to 4 blocks/s, 2 blocks/s until there is a span, so rain and cover are followed), and the predicted bite only ever moves sooner so the number never counts back up. Hidden for 3 s after an action bar message (the reeling minigame), reset by the BITE! title (1.2 s ignore window for the burst), by reeling in, and when the bobber is gone. Particles are never cancelled. Not taken from fishutils: its bite message and the caughtFish flag detection (the BITE! title notification covers it). Unit tests `display/BiteCountdownTest`, integration `BiteCountdownIntegrationTest`. Not run in game yet: check the number against the real bite, in rain and under a roof too.

- Rod not cast (2026-10-29, luna's ask; `display/RodIdle`, setting `rodIdleSeconds`, default 60, 10 to 600, slider "rod not cast after" on the settings bobber page): with a fishing rod in either hand and no own bobber (`player.fishHook == null`) for that many seconds, the mod hands `TACKLEBOX » Rod not cast for 60s` to the triggers (`TriggerEngine.onGameMessage`, not to chat). The "rod not cast" trigger preset turns it into a title and sound; without that trigger nothing shows, so the preset is the on switch. Rules (luna, "rod in hand only"): the clock starts only after the first cast since joining, fires once per wait, a new cast starts a new wait, putting the rod away resets it, leaving the server or a non-FishOnMC server forgets it all. It never casts. Unit tests `display/RodIdleTest`, integration `RodIdleIntegrationTest`. Not run in game yet: check it fires after a catch and not while the bobber is out, and that switching item resets it.
